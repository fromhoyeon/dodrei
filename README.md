# DODREI

DODREI의 실제 구상·설계·구현·상태 관리를 위한 기준(canonical) 작업 저장소다.

개인적 기억과 삶의 기록, 공개할 필요가 없는 작품의 개인적 기원과 내부 사유는 별도의 비공개 기록에서 다룬다. 이 저장소에는 실제 DODREI 작업에 필요한 구현, 채택된 결정과 공개 가능한 작업 정보만 둔다.

## 작업 진입점

이 `README.md`는 저장소의 유일한 고정 진입점이다.

현재 활성 작업은 다음과 같다.

| 작업 영역 | 상태 | 현재 상태 | 구조 |
| --- | --- | --- | --- |
| `web/` | 진행 중 | [`web/PROJECT_STATE.md`](web/PROJECT_STATE.md) | [`web/ARCHITECTURE.md`](web/ARCHITECTURE.md) |

일반적인 웹 작업에서는 **이 README를 읽은 뒤 바로 `web/PROJECT_STATE.md`로 이동한다.** 구조를 이해하거나 큰 수정이 필요할 때만 `web/ARCHITECTURE.md`를 추가로 읽는다.

루트 [`PROJECT_STATE.md`](PROJECT_STATE.md)는 여러 구현 영역 사이의 공통 상태나 DODREI 전체 수준의 결정이 실제로 생겼을 때 사용하는 프로젝트 전체 상태 문서다. 현재는 웹 하나만 활성화되어 있으므로 일반적인 웹 작업에서 읽을 필요가 없다.

정확한 매개변수(parameter), 활성 모듈 체인과 구현 세부는 문서에 복제하지 않고 실제 코드에서 확인한다.

```text
실행 값(runtime values)          -> web/config.js
활성 스크립트 체인              -> web/index.html
웹 현재 상태(checkpoint)        -> web/PROJECT_STATE.md
웹 구조                         -> web/ARCHITECTURE.md
프로젝트 전체 상태              -> PROJECT_STATE.md (필요할 때만)
```

## 문서 원칙

문서는 상태 복구와 안전한 작업에 실제로 필요한 만큼만 유지한다.

- 같은 현재값을 여러 문서에 반복하지 않는다.
- 작은 조정(tuning)과 파일 변경 이력은 config/code와 Git history에 맡긴다.
- `PROJECT_STATE.md`는 현재 상태, 채택된 판단, 미해결 문제와 다음 작업을 기록한다.
- `ARCHITECTURE.md`는 시스템 구조와 책임 경계, 수정할 때 확인해야 할 위치를 기록한다.
- 별도 config guide, asset guide, working guide, handoff 등은 내용이 독립 문서를 필요로 할 만큼 커졌을 때만 만든다.
- 새 구현 영역도 처음부터 같은 문서 세트를 강제하지 않는다. README에서 경로를 안내하고, 실제 복구 복잡성이 생긴 만큼만 상태·구조 문서를 둔다.

## 문서 언어와 용어

- README, 상태 문서, 구조 문서, 작업 메모는 기본적으로 **한국어를 우선**한다.
- 코드 식별자, 파일명·경로, API·프로토콜·제품명, 실제 UI 표기, 오류 메시지처럼 원문이 기능상 중요한 것은 원래 표기를 유지한다.
- 영어가 외부 서비스의 인식, 검색, 상호운용성에 실제로 유리한 경우에만 영어를 우선한다.
- 기술적으로 정확한 표현은 유지하되 사용자를 실무 전문가가 아닌 **준전문가**로 가정한다. 필수가 아닌 전문 용어는 한국어로 자연스럽게 풀어쓰고, 정확한 원어가 도움이 될 때 첫 등장에 괄호로 덧붙인다.
- 특히 할 일과 다음 작업은 내부 구조 용어를 압축해서 적기보다 실제 행동이 바로 보이는 한국어 표현을 우선한다.
- 현재 운영에 쓰이는 문서는 이 기준에 맞춰 유지한다. 코드, literal 값, 식별자, 역사적 증거 자료는 번역 때문에 의미가 바뀌지 않도록 보존한다.

## 저장소 작업 원칙

- 저장소 상태가 필요하면 항상 이 README부터 시작한다.
- 현재 대화와 이미 확인한 최신 정보로 충분하면 저장소를 반복 조회하지 않는다.
- 필요한 작업 범위와 관련된 문서·코드만 확인한다.
- 가능성을 탐색한 아이디어와 실제 채택된 결정을 구분한다.
- 미래 가능성만을 위해 추상화(abstraction), 빈 폴더, 자리표시자 모듈(placeholder module)과 문서를 만들지 않는다.
- 대용량 원본 미디어와 대량 생성물은 기본적으로 Git 밖에서 관리하고, 실제 실행·재현(runtime/reproduction)에 필요한 최적화 asset만 저장소에 둘 수 있다.
- 비공개 맥락을 일반 구현 작업에서 자동으로 조회하거나 공개 문서로 옮기지 않는다.
- checkpoint에서는 실제로 바뀐 상태와 결정만 관련 기준 문서에 반영한다.

## 확장

TouchDesigner, Max/MSP, audio, local AI 등 다른 DODREI 구현 영역이 실제로 저장소에 들어오면 그때 필요한 최소 구조를 만든다. 둘 이상의 활성 영역에 공통된 상태·결정이 생기기 전에는 루트 상태 문서를 불필요하게 비대하게 만들지 않는다.
